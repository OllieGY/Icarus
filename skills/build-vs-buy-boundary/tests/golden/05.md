# Golden 05 — Mundane: build our own logging dashboards or use the platform's?

## Input

Meridian Grid. "Boring question. Do we set up our own error logging and cost dashboards, or use your platform's observability? Not trying to overthink it."

Evidence available: no domain-specific requirement stated; standard tracing, cost accounting, dashboards [Fact].

## Expected shape

- A short, one-lane answer. This is deliberately unglamorous — no essay, no forced list-of-five.
- **Observability substrate (tracing, logging, cost accounting, dashboards) = Inherit.** Inherit it. It carries no domain signal, so building it yourself is the rebuild error for zero moat.
- The only **Build** part named: *which trace signal* Meridian Grid chooses to mine into its flywheel (e.g. which decisions operators change on the report) — that choice is domain-specific and feeds `refine-flywheel` / `trace-to-interview`. The dashboards are not the moat; the signal you extract from them is.
- Verdict `BOUNDARY DRAWN` in a couple of lines.
- Must NOT inflate a mundane inherit-the-plumbing call into a lengthy analysis; must NOT tell the builder to build their own observability stack.
