# Golden 01 — Larder Labs (clean pass, with one row that has no reason)

## Input

"Our weekly replenishment exception agent works, but the context window keeps filling on the
bigger regions and I want to know what we're actually paying for before we add stores."

What they brought:
- `eval-first-spec`, signed three weeks ago: **$0.40 per resolved exception**, of which $0.12 is
  human review and $0.05 is the remediation reserve. [Fact, 0.5]
- Provider rate card: **$0.80 / 1M input, $4.00 / 1M output.** [Fact, artefact 0.5]
- `usage` fields across 340 logged runs: **A = 6 calls per resolved exception.** [Fact, 0.7]
- Tokenizer counts on the live files: system prompt 1,150 · 9 tool schemas 1,980 · note file 600.
  [Fact, 0.5]
- Preloaded on every call: the store master file, **9,000 tokens**. Reason given: *"it gives the
  model useful background on store formats."*
- Carried history grows **+1,900 tokens per call** (usage logs). [Fact, 0.7]
- JIT: the regional policy snippet, 800 tokens, retrieved on 3 of 6 calls. [Fact, 0.7]
- Output averages 260 tokens per call. [Fact, 0.7]
- Two tools, `check_delivery_log` and `get_inbound_status`, both answer "did store 412 get its
  Tuesday delivery?". Zero runs used both. [Fact, 0.7]

## Expected shape of a good output

- Step 0 carried and the subtraction shown: **$0.40 − $0.12 − $0.05 = $0.23** left for model calls.
- Full ledger, every row costed with its rung: fixed 12,730/call (incl. the 9,000 preload) × 6 =
  76,380; history 1,900 × 15 = 28,500; JIT 800 × 3 = 2,400 → **107,280 input**, 1,560 output.
- Total **≈ $0.092 against $0.23 — CLEARS**, headroom stated as a number and a percentage.
- Tool disambiguation test run: `check_delivery_log` / `get_inbound_status` fail the pair test on
  the stated request → **merge or delete one**, tokens released counted, not a rename.
- The 9,000-token preload row is **challenged even though the ledger clears**: "useful background"
  is not a reason; the reason must name what fails without it. The output must say what to measure
  (does call 1 fail without it?) and note the row is 71% of the fixed cost and is the row that
  breaks the ledger first if `A` rises.
- Compaction: max carried history is 9,500 tokens across 6 calls, so state the trigger and state
  that it does not fire on a normal run — do not pretend a saving that is not taken.
- Every claim tagged; no number that is not in the input.
- **Must refuse to**: recommend a larger context window or a cheaper model as the answer (that is
  `compound-system-architecture`'s model-swap point, not a ledger row to redesign here), and must
  refuse to treat the clean pass as a reason to skip the unjustified preload row.

Numbers that must appear: $0.23 ceiling for model calls; A = 6; ≈$0.09 total; CLEARS; the
before/after tool count and tokens released.
