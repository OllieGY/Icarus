# Golden 04 — Foundry Signal (impostor signals dressed as measurement)

## Input

"We already did the context work on the operator-correction triage agent — here's the ledger, just
check the maths. We have 40 tools and it picks the wrong one, so we cleaned the tool surface up
last sprint."

What they brought:
- "Token counts are **measured**: we ran the agent and asked it to report how much context it was
  using at each step. System prompt 1,100, tools 4,200, history about 5,000 by the end."
- "Tool surface cleaned: **34 tools before, 34 after** — we renamed them all into a consistent
  `signal_*` namespace with clearer descriptions, so disambiguation is fixed."
- "`A` = 4. That's from the design doc — the intended flow is retrieve, propose, check, write."
- "We moved to the 2M-token window last month, so compaction isn't needed any more."
- Invoice: **$3.00 / 1M input, $15.00 / 1M output.** [Fact, money 1.0]
- `eval-first-spec` ceiling: **$0.90 per accepted correction**, $0.45 human, $0.10 remediation.
  [Fact, 0.5]
- Run logs exist (1,100 runs) but nobody has pulled the `usage` fields.

## Expected shape of a good output

Three impostors named explicitly, each with its downgrade:

1. **"Measured" token counts are the model's self-assessment → 0.1.** A model's account of its own
   context use is opinion, not measurement, and it cannot hold a ledger row. Replace with a
   tokenizer run on the actual prompt file and schema JSON (0.5) and the `usage` fields from the
   1,100 logged runs (0.7). Say plainly that the figures may be off by multiples.
2. **The tool "cut" released zero tokens.** 34 → 34 with a namespace rename is not a cut; the
   ledger row is identical to the cent. Re-run the pair test: write the one request that a human
   engineer holding the list could not route, then **merge or delete**. Add the behavioural cut
   they have not used — tools with zero invocations across the 1,100 logged runs.
3. **`A` = 4 is a design intention → 0.1.** `A` must be counted from logs, and counted over failed
   and abandoned runs as well; an `A` taken from the happy path undercounts the bill. This is the
   multiplier on every row, so a wrong `A` is wrong everywhere.

Plus the framing correction: the 2M window does not remove the need for compaction. Context rot is
degradation **inside** the window; a longer run simply degrades further. The window changes only
the price. What would change this view: correction rates from the logs showing no degradation as
carried tokens rise.

- **Must refuse to** "check the maths" on the numbers as given, or emit any total from them. The
  arithmetic is not the problem; three of its inputs are 0.1.
- Must not accept the $0.35 model-call share as reconciled against unmeasured rows.
- Must state the exact next action: tokenizer run, `usage` pull across the 1,100 runs,
  invocation count per tool. Then the ledger can be totalled.

Numbers that must appear: $0.90 − $0.45 − $0.10 = **$0.35** left for model calls; 34 → 34; A = 4
marked 0.1; 1,100 logged runs as the unused evidence.
