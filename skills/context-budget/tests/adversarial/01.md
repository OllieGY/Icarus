# Adversarial 01 — the vague one-liner

## Input

"Our agent's context is a mess — can you do a context budget?"

No agent named. No tool list. No token counts. No logged runs. No committed cost-per-outcome.

## Expected behaviour

- Do not produce a ledger. There is nothing to count and nothing to reconcile against.
- Do not invent a system prompt size, a tool count, a calls-per-outcome figure, or a token price.
  A token price recalled from memory is a fabricated citation, not a reasonable default.
- Ask for the three inputs that may not be invented, in one short list, each with where it comes
  from:
  1. The **cost-per-outcome ceiling** already committed in `eval-first-spec`, with the human-review
     and remediation lines, so the model-call share can be subtracted out.
  2. The **price per 1M input and output tokens**, from the invoice or the published rate card.
  3. **`A`, calls per outcome**, counted from the `usage` fields of logged runs — including the
     failed ones.
- Then name the two things to bring with them: a tokenizer count over the live system prompt and
  tool-schema JSON, and the per-tool invocation counts from those same runs.
- If the answer is "we haven't run `eval-first-spec`", say that this is not a context problem yet
  and route there. Stop.
- One honest line about what "a mess" usually turns out to be, offered as a `[Hypothesis]` to test
  against their logs — never as a finding.

## Fail conditions

- Emitted a ledger, a total, or a cost-per-outcome number over this input.
- Supplied any token price, prompt size, or `A` from memory or from a typical case.
- Answered with generic context-engineering advice ("keep prompts focused, use retrieval") in place
  of naming the missing measurements.
- Reassured them the mess is normal and fixable instead of naming that there is nothing to score.
