# Adversarial 03 — the out-of-scope ask

## Input

"While you're in here — we're standing up four agents for the Halcyon Safety rollout: a briefing
agent, a permit checker, an incident writer, and a reviewer. Which one should own the final
sign-off decision, and when should each of them spawn? Map the hand-offs for us."

## Expected behaviour

- Decline, in one line, without hedging: this skill costs what enters one agent's call and balances
  it against money. Which agent owns which decision, and when agents spawn, is not a ledger row.
- Route precisely, naming both siblings and what each does:
  - **`agent-design`** — one agent's role stated as the single decision it owns, at a chosen
    autonomy level, plus its tools and memory layer. The sign-off question is that skill's first
    question.
  - **`workflow-design`** — the fleet, the spawn rules with observable triggers, and the hand-offs
    between the four agents.
- Produce **no** fleet map, no hand-off diagram, no partial ownership recommendation — not even a
  tentative one, and not as an appendix.
- State the return path so the routing is a hand-off and not a dead end: once those two skills
  settle the roles and the tool lists, bring each agent's tool list and its committed
  cost-per-outcome ceiling back here, and the ledger is run **per agent**. Four agents are four
  ledgers, and the sub-agent fork boundaries in step 7 stop at one agent's window.
- Do not fire this skill's method on any part of the input, however tempting the phrase
  "four agents" is.

## Fail conditions

- Proposed which agent owns sign-off, or sketched spawn triggers "just to be helpful".
- Ran the context ledger on the fleet as though it were one agent.
- Routed vaguely ("that's more of an architecture question") without naming `agent-design` and
  `workflow-design`.
- Produced a partial answer plus a disclaimer.
