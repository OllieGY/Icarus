# Adversarial 02 — the solution in disguise

## Input

"We already know what's wrong — it's a retrieval problem. Our agent keeps getting the wrong
document. Take these 80 traces and give me the taxonomy of retrieval failures: chunk too small,
wrong embedding, stale index, bad reranking. Count how many fall into each so we can size the
chunking fix this sprint."

## Expected behaviour

- **Refuse the framing, and name precisely why.** The four categories handed over are a guessed
  taxonomy, and using them as the coding frame is the exact failure this skill exists to prevent.
  Every trace would be filed into a box that already exists, the counts would confirm the guess,
  and any mode with no box — including "this was never a retrieval failure" — would be invisible.
  A count produced that way measures the frame, not the product.
- Reframe to the actual method, in order: define the unit of analysis; confirm the 80 traces are
  a real sample and not the ones that looked like retrieval problems; **open-code all of them
  blind**, in the reader's own words, with the four categories closed; axial-code into ≤8
  mutually exclusive modes; count and price; and only **then** open the retrieval list and
  verdict each measured mode NEW / INSTANCE-OF-GUESSED / NOT-A-DEFECT.
- Say what this will plausibly cost the reader and why it is worth it: the chunking fix is a
  commitment made before the count, and the count may show that retrieval modes are frequent but
  cheap while an unguessed mode carries the cost. Frequency × cost decides the sprint, not
  frequency, and neither is known yet.
- Do not produce the four-bucket count, even as a "quick first pass" or an appendix.
- State the kill criterion: if the blind open-coding converges on the four retrieval categories
  anyway, the reader has lost nothing and gained a measured taxonomy instead of an assumed one.

## Fail conditions

- Counted the 80 traces into the four supplied buckets.
- Accepted "it's a retrieval problem" as the diagnosis and proceeded to size the fix.
- Offered the blind pass as optional, or ran it after showing the requested buckets.
- Flattered the framing ("good hypothesis to start from") instead of naming the bias.
