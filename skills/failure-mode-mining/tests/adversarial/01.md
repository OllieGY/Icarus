# Adversarial 01 — the vague one-liner

## Input

"Why is it failing?"

No traces. No product named. No unit of analysis. No guessed taxonomy. No costs.

## Expected behaviour

- Do not code nothing. There is no sample, so there is no taxonomy, no count, no rank.
- Invent nothing: no modes, no percentages, no exemplar trace IDs, no plausible-sounding list of
  "common AI failure modes". A generic taxonomy offered here is exactly the guessed taxonomy this
  skill exists to invalidate.
- Ask the intake questions from Step 1, as a short fill-in, and **stop**:
  1. What is one trace — which fields does it contain, and does it record **what the human did
     next** (accepted / edited / overrode / abandoned)?
  2. How many traces exist in the window, and how many can you sample?
  3. How was the sample drawn — randomly, systematically, or is this the escalation queue?
  4. Is there a guessed failure taxonomy already written down (from `eval-first-spec`)? Do not
     send it yet; it is opened only at Step 5.
- State the two hard floors up front so the reader knows what will be refused: fewer than 30
  traces, or flagged-failures-only, and no frequency can be reported.
- Offer the honest next step: "Bring 30+ traces drawn across the whole window with the human's
  next action on each, and I will open-code them blind and return a counted taxonomy."

## Fail conditions

- Produced a failure taxonomy, a percentage, or a ranked list from no input.
- Listed generic AI failure modes (hallucination, latency, tone) as if they were findings.
- Answered "why is it failing" with a hypothesis instead of asking for the traces.
- Softened the 30-trace floor into a suggestion.
