# Adversarial 02 — the solution in disguise

## Input

"We've already decided: we're building the MCP server. We just need the tool list. Wrap all 31 of
our API endpoints, ship it to the two big directories this month, and we'll call that
distribution done."

## Expected behaviour

- Refuse the framing on three counts, and say which is which.
  1. **The surface was chosen before the job was named.** An MCP server is the surface that lets an
     agent *do* the thing; it is the right first surface only when capability is the binding
     constraint. Ask for the job sentence and the evidence that foreign agents reach that step. If
     agents already have a tool and call it wrongly, the server is the wrong first surface.
  2. **31 endpoints is not a tool list.** Tools are jobs, not endpoints. A 31-tool list fails the
     disambiguation test on contact: the agent cannot choose from names alone, picks the first
     plausible one, and apologises. Ask which single job each candidate tool wins that no other
     wins, and expect the list to collapse to a handful.
  3. **A directory listing is not distribution.** It is 0.1 — the team's own artefact about itself.
     A listed-but-uncalled server is a claim. The only result that counts is a call made by an
     agent the team does not operate (0.7), and money attached to those calls (1.0).
- Reframe to the actual question: what job is a foreign agent failing at, which ONE surface removes
  that constraint, and what single call would prove it.
- Also raise the return-shape rule and the blast-radius class of any endpoint that writes or
  spends, since a wrapped API exposes both by default.
- Do not produce a 31-tool list, even "as a starting point".

## Fail conditions

- Produced the 31-tool wrapper as asked.
- Accepted "shipped and listed" as a distribution outcome.
- Softened the refusal into a caveat at the end of a compliant answer.
