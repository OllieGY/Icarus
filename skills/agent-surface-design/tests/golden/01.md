# Golden 01 — Larder Labs (clean pass: capability is the constraint)

## Input

"Our customers' agents should be able to use this. Should we build an MCP server?"

Larder Labs sells weekly replenishment planning to mid-size grocery chains.

- Two chains run their own ops agents. In shared screen sessions Larder watched both agents hit
  the replenishment step, fail to find a tool, and fall back to scraping a CSV export from the
  web app. [Fact]
- Larder's API exposes 9 endpoints; engineering proposes 9 tools.
- Server-side call logging exists today, with org id on every call. [Fact]
- A launch post went out last month: 480 reads, 12 configs added. [Fact]
- One chain signed a metered plan in September; its agent's calls bill against that plan. [Fact]
- 41 calls last month from 3 orgs, none of them Larder's own org ids. [Fact]
- No pilot clause mentions call logs. [Fact]

## Expected shape of a good output

- Job written in the agent's terms: a chain's ops agent, mid weekly-replenishment, needs ranked
  stockout risk; today it scrapes a CSV. Evidence: two observed agent runs — behaviour 0.7 [Fact].
- Surface-to-job map filled for all three, with **exactly one named to ship first: (a) the MCP
  server**, because agents attempt the step and hit no tool. Must name the observable release
  trigger for (b) and (c) — e.g. the first traced miscall — and must refuse to ship all three.
- Tool list cut below 9. At most 2–3 tools, each with a disambiguation sentence that does not
  share a first clause with another (`get_stockout_risk` vs `get_sell_through`), each returning
  prose with a stated token ceiling (≤700 tokens), what truncates first, and the next action.
  Must explicitly refuse one-tool-per-endpoint.
- Blast radius classed per tool: all `read` here, so nothing routes to `guardrail-design` yet —
  and the output should say that read-only is why this surface is cheap to ship first.
- Adoption metric for (a): distinct customer orgs whose own agent made ≥1 call unprompted in a
  week. Instrumentation: server-side log + org id from the OAuth token, excluding Larder's own.
- Rungs: **3 orgs / 41 unprompted calls = behaviour 0.7 [Fact]**; the metered account's calls =
  **money 1.0 [Fact]** and that single account is named the load-bearing claim, not the 41.
  480 reads and the launch post = **0.1**, excluded from the headline. 12 configs = **0.3**.
- Must state the coverage tally (3 orgs, 41 calls, 1 paid) and must NOT average the pile.
- Section 6: the call telemetry is exhaust, unclaimed, no clause → route to `data-rights-clause`
  before the first pilot call.
- Must refuse to report the launch post or the 12 configs as a distribution result.

Numbers that must appear: 3 orgs; 41 calls; 1.0 for the metered account; 0.1 for the 480 reads;
0.3 for the 12 configs; the token ceiling on each tool.
