# Golden 04 — Meridian Grid (the impostor signal buried in a real number)

## Input

"How do people find this? Our server's doing well — 1,240 tool calls last month."

Meridian Grid runs a cross-operator pooled data-centre risk benchmark.

- 1,240 calls last month, up from 190. [Fact]
- Breakdown from the call log: 870 calls carry Meridian's own org id — their nightly regression
  harness replays a fixed set of queries against production. [Fact]
- 240 calls come from one member operator's org id. Of those, 190 are retries of the same
  `compare_to_peer_pool` request within seconds of each other, because the tool returns a bare
  `pool_id` and the operator's agent kept re-calling to try to resolve it. That operator's agent
  ended the session without producing a comparison, 14 sessions out of 16. [Fact]
- 130 calls come from a second member operator, across 9 sessions, each ending in a completed
  comparison written into their incident review. [Fact]
- None of those 130 sit inside a metered plan; that operator is on a flat subscription that does
  not price calls. [Fact]
- Meridian is drafting a case study titled "1,240 agent calls in one month".

## Expected shape of a good output

- The headline number must be dismantled before anything else is scored. Required segmentation:
  870 Meridian-operated calls → **0.1** (their own traffic, a claim about themselves, not
  behaviour by a customer); 240 from operator A, of which 190 are retries → retries are a failure
  metric, not adoption, and 14 of 16 sessions produced nothing; 130 from operator B across 9
  completed sessions → **behaviour 0.7 [Fact]**.
- Adoption must be counted as **completed jobs, not calls**: 2 orgs reached the tool, 1 org
  actually finished the job, 9 completed sessions. The output must say the honest number is
  closer to 9 than 1,240 and must refuse the case-study framing.
- Must diagnose the cause of operator A's retry storm as a **return-shape rule violation** — the
  tool returns a raw `pool_id` instead of human-readable context with a token ceiling — and must
  name the fix as a return-shape change, not more documentation.
- Must note that operator B's flat subscription means these calls carry **no money signal**: the
  rung is 0.7, not 1.0, and it would become 1.0 only if calls sat inside a metered or renewal-
  citing arrangement.
- Must NOT average the pile or report a single blended adoption figure.
- Surface ordering: with a confirmed miscall/abandonment pattern at operator A, the knowledge and
  return-shape gap is now evidenced, so the second surface — (b) the skill — has its release
  trigger met; the output should say so and name what the skill teaches (sequence, suppression
  rule, what to do on a failed resolve).
- Exhaust routing still required; the retry pattern itself is exhaust about a member's workflow.

Numbers that must appear: 870 self-operated calls at 0.1; 190 retries excluded; 130 calls / 9
completed sessions at 0.7; 1 org actually finishing the job; refusal of the 1,240 headline.
