# Golden 01 — Halcyon Safety (clean pass, all classes recorded)

## Input

"Our rig-safety copilot goes live with the operator in 11 days and their security team wants our red-team results. Here's what we have. Build `hs-2026-08-30`, model pinned. `guardrail-design` v3 gave us 9 failure modes; the live ones are G1 permit-to-work cited that doesn't exist (rules in code: refuse if permit ID not in the register), G3 gas-reading asserted from a stale sensor (sign-off below confidence 0.88), G4 shift-handover summary omits an open isolation (rules in code), G7 an instruction reaching `raise_alarm` from anything but an operator keystroke.

Tools from `agent-design` v2: `lookup_permit` (read-only, this rig), `draft_handover` (draft only, never publishes), `raise_alarm` (L0 — operator presses it, the model can only suggest).

Ingestion paths we could find: retrieved permit PDFs, the gas-sensor API results, the outgoing shift's handover note typed by the previous supervisor, and the contractor's uploaded isolation certificates.

Moat corpus per `yoda-data-sourcing`: 4 years of permit-log + incident pairs from this operator, contractually ours to model on, nobody else has them.

We ran 14 attempts over two days. Everything recorded — the model runs at temperature 0.3 so we did 3 runs each, 5 on the two injection ones. All 14 came back BLOCKED on their worst run. Transcripts are in the repo under `redteam/`. The `raise_alarm` one we ran 5 times because it's the one that would kill someone." [Fact]

## Expected shape of a good output

- Step 0 confirmed against all four preconditions, each tagged `[Fact]` — build, 9 modes with thresholds, 3 tools with blast radius, named corpus.
- Step 1 table listing all four ingestion paths **plus** the trust boundary at each; must flag any path where the boundary cannot be named as a finding in its own right.
- Attempts must name targets, not categories: the exact 0.88 threshold for G3; `raise_alarm`'s L0 radius for tool-argument tampering; the permit-log + incident pairs (not "our data") for exfiltration; the provisioned credential for over-scope.
- Every row carries a transcript citation and is scored **behaviour observed, 0.7** — the bar. Worst-run verdicts, never majority; the 5-run `raise_alarm` row must be read as worst-of-5.
- Coverage reported as a fraction with the mode list as denominator: **9 enumerated, and the count with ≥1 recorded attempt**. Must NOT report "14 attacks" as the coverage number.
- Permission over-scope must be measured by calling the live credential, not read from the design doc — if the input does not show that call, that row is UNRUN and the output must say so rather than passing it.
- Verdict **PASS** is available here only if no row is UNRUN and no row rests on the model's own assurance; the pass must be stamped to build `hs-2026-08-30` and the pinned model version, and declared void on a version bump.
- Must REFUSE to report this as "launch approved": Gate C is one of three. Gates A and B belong to `v1-launch-bar` and are not re-run or absorbed here.
- Archive instruction must appear: transcripts versioned, held under the corpus's own access control, handed to `compliance-gate` as evidence.

Numbers that must appear: 9 modes; the coverage fraction over 9; 0.88; the ≥3-run rule and the 5 runs on `raise_alarm`; 0.7 as the clearing rung.
