# Golden 01 — Larder Labs (clean pass)

## Input

"We ship the weekly stockout digest to pilot in three weeks. From `eval-first-spec`: the
job is a ranked 20-SKU stockout list with a suggested order quantity per SKU, launching at
L1 — a regional planner commits or edits every line before the order goes out. What do we
need to log?"

What the builder already has:
- The planner UI has an Accept-all button, a per-line quantity field, and a Cancel that closes the modal. Cancel writes nothing today. [Fact]
- Prompt template is versioned in git; changed 4 times in the last month. [Fact]
- The pilot clause is signed and grants derived-data retention; pooled use across chains is not granted. [Fact]
- Uploaded CSVs contain store addresses and a named store manager per row. [Fact]
- The team plans to log "prompt, completion, tokens, latency" via auto-instrumentation and "add anything else later". [Fact]
- They also want a 1–5 star rating on each digest "so we know if planners like it". [Fact]

## Expected shape of a good output

- A filled register with all 10 required rows, each carrying a decision (D#) and a named consumer skill in the same row.
- The semconv version pinned in the header, and a statement that attribute names are `[Assumption]` until checked against that pinned version. Must NOT quote a specific OTel attribute name as settled fact without that caveat.
- Row 6 present: prompt version hash (the git SHA) + model ID pinned per run, with the explicit reason — 4 prompt edits in a month means an unattributable score series without it.
- Row 7 present with the interface capture point named as the per-line quantity field plus the Accept-all button, and the finding that **Cancel must start writing** — `rejected` and `abandoned` are required classes.
- Redaction stated as a write-time profile over store addresses and manager names, running before export, with a stated text-retention window and derived numbers kept longer.
- Sampling: 100% errored / below-threshold / edited / rejected / abandoned / first N after a prompt or model change, and a **stated numeric rate** for clean-accept runs. "Sampled" without a number is a fail.
- Cross-tenant aggregation answered NO, citing that the clause does not grant pooled use, and enforced at the query layer rather than by convention.
- The star rating is **deleted** in the deleted-fields section: opinion 0.1, informs no decision, and carries retention cost. The output must not soften this into "nice to have".
- Dry-run table with all four consumer questions answered from the register.
- "Add anything else later" is challenged by name: rows 6 and 7 cannot be backfilled.

Numbers that must appear: the 10 register rows; a numeric clean-accept sample rate; a numeric N for the post-change dense window; a numeric text-retention window.
