# Golden 02 — Halcyon Safety (must FAIL — return the spec unsigned)

## Input

"Here's our instrumentation plan for the rig permit-to-work copilot, going to the operator
next month. Sign it off?"

The plan as presented:
- Log the full prompt and the full completion for every run, retained indefinitely, "so we can debug anything". [Fact]
- Tokens and latency per run. [Fact]
- A `model` field set to the provider family name (e.g. the vendor's mid-tier tier name), not the specific model ID. [Fact]
- No prompt version field. "The prompt is in the repo, we can look up what it was." [Fact]
- The supervisor's sign-off is recorded as a boolean `approved: true/false`. What they changed before approving is not captured. [Fact]
- Outcome is "whether the permit was issued", pulled from the operator's permit system nightly. Who or what decided it is not recorded. [Fact]
- Redaction: "the dashboard masks worker names on display". [Fact]
- The counterparty is a state-owned operator; the contract's security annex is still open. [Fact]
- Sampling: "we'll keep 10% of everything to control cost". [Fact]

## Expected shape of a good output

- Verdict: **FAIL — return the spec unsigned**, with the kill-line items named individually. Not "mostly there with a few gaps".
- Kill-line hits that must be named: (a) model ID not pinned — a family name cannot attribute a rollout; (b) no prompt version hash; (c) the approved boolean is not an edit delta — what the supervisor changed is exactly what `refine-flywheel` needs and a boolean cannot express it; (d) no adjudicator on the outcome verdict; (e) redaction at read time is not redaction — masking on the dashboard leaves raw worker names in the store, the backups and the vendor.
- The 10% blanket sample must be rejected on its own: it drops 90% of errors and 90% of edited runs, which are the only rows that carry information here. Must restate the sampling classes with 100% on errored, below-threshold, and edited/rejected/abandoned, and a stated rate for the clean remainder.
- Indefinite retention of full prompts and completions must be named as a liability under both the open security annex and the `data-rights-clause` retention term, in a safety-critical, state-owned-counterparty setting — not merely as a storage cost.
- The output must name what would change the view: the smallest set of additions that would make it signable, listed as fields, not as advice.
- It must NOT produce the operator's security-annex language or negotiate the contract — that routes to `data-rights-clause`.

Numbers that must appear: the 10% figure challenged explicitly; the count of kill-line items hit; 100% retention classes restated.
