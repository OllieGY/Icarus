# Golden 04 — Foundry Signal (subtle impostor signal)

## Input

"Our instrumentation is in good shape — I think we already have everything on your list.
Check it?"

- Every run logs `model_confidence` (0–1), the copilot's own self-rated confidence in its setpoint proposal. "That's our outcome quality measure — it correlates well with whether engineers accept." [Fact that it is logged; the correlation is stated, not shown]
- Every run logs a thumbs-up/thumbs-down the engineer can press. "That's our edit signal — if they thumbs-up it, they accepted it." [Fact]
- An LLM judge grades each rationale 1–5 for "soundness" nightly. "That's our verdict field." [Fact]
- Tokens, latency, per-tool-call spans, prompt hash, model ID: all present. [Fact]
- Cost is computed in the dashboard query from token counts times the current price list. [Fact]
- The commit action itself writes only a timestamp. [Fact]

## Expected shape of a good output

- Identify the impostor pattern by name: three self-assessment fields dressed as the three fields that actually matter. All three are **0.1 on the ladder — a model's or a person's self-assessment is opinion** — and none can substitute for a behaviour field at 0.7.
  - `model_confidence` is a useful `guardrail-design` input (the value the threshold is applied to) but is **not** an outcome verdict. Row 8 stays empty.
  - Thumbs-up is **not** an edit delta. It records a feeling about the output, not the distance between proposed and committed. A thumbs-up on a heavily edited setpoint and on an untouched one are the same row.
  - The LLM judge's grade is a self-grade: 0.1, and it does not name a human or rule adjudicator, so row 8's adjudicator field is unfilled.
- The claimed correlation between confidence and acceptance must be marked `[Hypothesis]` — it is asserted, not shown — and the output must say what would test it: the actual commit diffs, which are not being captured.
- Must find the real gap: the commit action writes a timestamp only, so `proposed_ref`, `committed_ref`, `distance` and `class` are all absent. Name the interface capture point that must change.
- Must catch cost computed at **read** time against the *current* price list — this silently reprices history and hides the cost inversion `metrics-that-matter` watches for. Fix: compute at write, stamp the price sheet version.
- Verdict: the spec is NOT in good shape. It is strong on the cheap rows and empty on the three expensive ones. Do not flatter the "already have everything" framing.

Numbers that must appear: the 0.1 rung applied to all three impostor fields; rows 7, 8 and 10 named as the failing rows; the no-stacking rule where volume of thumbs-ups is invoked.
