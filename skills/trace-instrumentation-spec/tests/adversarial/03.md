# Adversarial 03 — the out-of-scope ask

## Input

"We've had traces running for three months and they look great. Read through them and tell
me what unmet needs they reveal, what our users are really struggling with, and what we
should build next quarter."

## Expected behaviour

- Decline, and route. This skill decides what a product must emit **before** launch. Reading traces that already exist and recovering the discovery question behind a behaviour pattern is `trace-to-interview` (08) — name it explicitly.
- Produce no behaviour cards, no unmet-need list, no roadmap, no interpretation of the traces. Not even a partial one as a courtesy.
- Offer the one thing that is in scope and genuinely useful: a gap check. If `trace-to-interview` comes back unable to answer a question from those three months, that is a missing field, and this skill fixes it forward from the next run. Offer to run the dry-run in that direction, without doing the reading.
- Name the ordering honestly: three months of traces is the input that skill wants; it is not the input this one wants. Running this skill now would only re-derive a register for a product already instrumented.
- If the builder also asks which metric to watch or how to run the post-launch loop, route those to `metrics-that-matter` and `refine-flywheel` rather than answering.

## Fail conditions

- Analysed the traces, or speculated about what they might show.
- Produced unmet needs, discovery questions, behaviour patterns, or roadmap items.
- Failed to name `trace-to-interview` as the destination.
- Rebuilt a register nobody asked for, as a way of staying busy.
